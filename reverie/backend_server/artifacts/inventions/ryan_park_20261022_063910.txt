Ryan Park built a modular, accessible mobile-app backend that connects customer features with catalog, inventory, and order services. Written in TypeScript on Node.js, it uses small service modules, REST APIs, and a lightweight database layer. When the stock service is slow or unavailable, an inventory fallback reads recently cached stock data, marks potentially stale availability, and prevents customers from ordering more units than the cached quantity suggests. The order service also runs validation and safety checks before confirming purchases, avoiding duplicate or oversized orders during partial outages.

To verify the system, Ryan created integration tests using a testing framework, mocked service responses, and failure-injection scenarios. The tests simulate stock-service timeouts, malformed responses, and expired cache data, then confirm that the fallback remains functional and that unsafe orders are stopped rather than silently accepted. He also added request timeouts, structured logs, and cache-expiration rules to control uncached API latency.

The project was motivated by Ryan’s belief that dependable community-facing applications should degrade gracefully rather than fail completely. It supports his broader goal of making the modular mobile app more accessible, resilient, and easier to improve as new features are added.
